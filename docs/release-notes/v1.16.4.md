# MineBackup - 存档时光机 - v1.16.4

这是一次以**备份与还原的数据安全、并发可靠性和配置兼容性**为主的修复更新，重点修复失败回滚、Smart Backup 保留策略和覆盖备份中的问题。

MineBackup-Mod 项目仓库：[https://github.com/Leafuke/MineBackup-Mod](https://github.com/Leafuke/MineBackup-Mod)
FolderRewind 项目仓库（第二代存档时光机）：[https://github.com/Leafuke/FolderRewind](https://github.com/Leafuke/FolderRewind)

## 主要更新

1. **修复还原与备份保留策略的失败保护。** 还原提交后，快照清理失败只提示警告，不再从已部分删除的快照回滚；Smart Backup 归档重建采用事务替换，无法完整回滚时保留恢复副本并报告位置。提交前取消仍会回滚原世界。
2. **修复历史记录定位与备份链一致性。** 历史还原按配置中的世界身份解析目标，避免嵌套世界路径与存储目录名混淆；新归档使用唯一文件名，避免同秒备份覆盖和增量链自引用。同秒历史保留提交顺序。
3. **重建覆盖备份。** 覆盖模式每次使用过滤后的相对文件清单创建独立归档，正确处理排除项和已删除文件，并保护原有 Full / Smart 归档及恢复链。接受额外压缩时间和临时磁盘空间，以加强失败保护。
4. **提高增量变化检测精度。** 文件状态记录稳定的亚秒 UTC 修改时间，修复同一秒内等长内容修改可能漏检的问题；旧秒级元数据可继续读取，首次扫描会保守刷新。大小与修改时间均被刻意保持的内容变化仍不保证识别。
5. **统一还原前的安全备份。** 修复桌面端重复安全备份、备份失败后仍继续还原，以及过早执行保留策略导致选定旧归档被删除的问题；热还原复用已完成的安全备份，保留策略延迟到还原提交之后。
6. **修复配置与历史的并发更新。** 界面使用编辑草稿并按字段提交，后台读取配置快照，避免失效引用、已删除配置被重新插入和云字段被旧草稿覆盖；保留策略在最新历史上应用变更，保护其他世界和最新的备注、重要标记及云状态。
7. **修复配置、自动备份与云同步结果。** 覆盖模式及 Smart 数量为 0（不限）的设置可正确保存、重载和导入；开服监视按世界所属配置执行，并识别多个活动世界；云下载汇总成功与失败，部分失败不会再显示整体成功。
8. **修复历史窗口窄屏布局。** 根据两栏最小宽度和实际间距切换单栏，避免窗口缩放触发非法宽度约束及 Debug 断言。

9. **补齐发布前边界修复。** 定时任务按稳定世界身份管理，重排后仍可停止且不会重复启动；覆盖保留检查忽略无关文件；mods 和任意目录备份按源路径执行保留策略，并先提交历史。旧 Smart 反向及自定义还原使用匹配的预检，缺失云材料先补链再验证；元数据回滚清理失败时保留归档及恢复副本。

## 兼容性说明

- 保留现有配置字段、历史结构、归档类型标记和合法旧备份的读取能力，元数据版本仍为 `3.0`，便携配置 schema 不变。
- **旧覆盖归档如果使用了绝对路径或越界路径布局，将在修改世界之前被明确拒绝还原。** MineBackup 不会自动改写或猜测这类归档的世界根目录，也不会删除原归档。
- 请关注快照清理或事务回滚失败提示中报告的恢复副本路径。程序会保留需要人工处理的恢复材料。

# MineBackup - Archive Time Machine - v1.16.4

This maintenance release focuses on **backup and restore data safety, concurrency reliability, and configuration compatibility**, with fixes for rollback failures, Smart Backup retention, and Overwrite backups.

MineBackup-Mod repository: [https://github.com/Leafuke/MineBackup-Mod](https://github.com/Leafuke/MineBackup-Mod)
FolderRewind repository (2nd-generation Archive Time Machine): [https://github.com/Leafuke/FolderRewind](https://github.com/Leafuke/FolderRewind)

## What's New

1. **Safer restore and retention failure handling.** Snapshot cleanup failures after a committed restore now produce warnings without rolling back from a partially deleted snapshot. Smart Backup rebuilding uses transactional replacement; incomplete rollback keeps recovery copies and reports their location. Cancellation before commit still restores the original world.
2. **Correct world targeting and backup chain identities.** History restores resolve configured world identities instead of confusing nested paths with storage folder names. Unique archive filenames prevent same-second collisions and self-referencing incremental chains. History retains commit order when timestamps are equal.
3. **Rebuilt Overwrite backups.** Each Overwrite backup creates an independent archive from a filtered relative file list, correctly applies exclusions and deletions, and protects existing Full / Smart archives and restore chains. This uses additional compression time and temporary disk space for safer failure handling.
4. **More precise incremental change detection.** Stable subsecond UTC file timestamps detect same-size changes within a second. Older second-resolution metadata remains readable and is conservatively refreshed on the first scan. Changes that deliberately preserve both file size and modification time are still not guaranteed to be detected.
5. **Unified safety backups before restore.** Fixed duplicate desktop safety backups, restores continuing after a failed safety backup, and retention deleting the selected old archive too early. Hot restore reuses completed safety backups, and retention runs only after restore commits.
6. **Safer concurrent configuration and history updates.** The UI applies field changes from an editing draft while background work reads snapshots, preventing stale references, deleted profile resurrection, and unrelated cloud-field overwrites. Retention applies changes to the latest history, preserving other worlds and current notes, important flags, and cloud status.
7. **Correct settings, game-start backups, and cloud results.** Overwrite mode and unlimited Smart backups (`0`) survive save, reload, and import. Game-start monitoring follows each world's own configuration and detects multiple active worlds. Cloud sync reports successful and failed downloads accurately, including partial failures.
8. **Fixed narrow history-window layouts.** Single-column mode now follows the actual minimum column widths and spacing, avoiding invalid width constraints and Debug assertions during resizing.

9. **Additional reliability fixes.** Automatic timers use stable world identities and remain stoppable after reordering without duplicate starts. Overwrite retention ignores unrelated files. Mods and arbitrary-folder backups apply retention by source path after history commit. Legacy Smart reverse/custom restores use matching preflight checks, with missing cloud materials repaired before verification. Failed metadata rollback cleanup retains archives and recovery copies.

## Compatibility Notes

- Existing configuration fields, history structures, archive type markers, and valid older backups remain supported. Metadata stays at version `3.0`, and the portable configuration schema is unchanged.
- **Legacy Overwrite archives with absolute or escaping member paths are explicitly refused before world modification.** MineBackup does not rewrite these archives or guess their world root, and leaves the original archive intact.
- Snapshot cleanup and incomplete rollback warnings identify retained recovery copies that may require manual handling.

# ADR 0005：结构化会话日志与单一日志门面

状态：已接受

MineBackup 使用自有结构化日志门面作为 GUI、后台任务、特殊模式和 KnotLink
的唯一日志入口：记录先进入线程安全的有界会话日志，再由固定版本的 spdlog
异步写入本地轮转文件或特殊模式控制台；ImGui 只读取不可变记录。业务 API
不依赖 ImGui、spdlog 或控制台对象，级别、类别、事件 ID 和上下文也不从消息
前缀推断。

这一选择以阻塞式异步队列和正常退出完整排空换取诊断可靠性，同时允许界面
独立淘汰较早记录以保持固定内存。它拒绝继续使用退出时聚合文本、分域日志
文件、遥测、联网日志、数据库和 JSON-only 输出；本地文件保留真实路径，
只有用户主动导出的诊断日志执行已知信息脱敏。

结果是文件后端失败或关闭时，会话日志与特殊模式控制台仍可工作；日志格式、
持久化和 UI 可以分别演进。代价是高日志压力可能短暂阻塞生产者，崩溃或断电
仍可能丢失最近一次周期刷新后的记录，诊断导出也不能自动识别任意外部程序
输出中的所有秘密。

本地轮转文件采用“可读正文、按需扩展”的文本策略：Info 模式仅显示带括号的
时间、级别、类别与消息，Debug 模式才追加事件 ID、线程、上下文和源码位置。
完整会话 ID 与序号继续存在于结构化记录和诊断导出中，但不在每一行本地日志
中重复；本地文件以短会话 ID 的开始/结束边界区分多次运行。这是在不拆分第二
套 JSON 日志的前提下，兼顾用户直接阅读与工程诊断能力。

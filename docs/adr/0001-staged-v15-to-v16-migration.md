# ADR 0001：对 1.15 数据采用分阶段单向迁移

日期：2026-07-10
状态：已接受

## 背景

直接用 FolderRewind v3 覆盖 MineBackup 1.15 的数据边界会使现有 history、Smart 链和云清单失去可用性。长期双写又会把临时兼容变成永久一致性负担。

## 决策

1. 1.16 是唯一内置 1.15 迁移器的版本；配置和历史在启动时迁移，世界和云 metadata 按需迁移。
2. 迁移器只读旧格式并只写 FolderRewind v3；不双写，不支持升级后由 1.15 继续写同一数据。
3. 覆盖规范 JSON 前保留恢复快照，归档包原地复用。
4. 有效新格式优先；不完整链降级并强制下一次 Full，无法安全映射的云历史不允许覆盖。
5. 旧格式转换通过编译开关和独立 reader/adapter 隔离，1.17 删除；永久迁移协调边界见 ADR 0002。

## 结果

- 1.15 用户可保留历史和完整 Smart 链，同时 1.16 正常数据边界保持 FolderRewind-only。
- 升级是单向操作；需要回退时只能使用升级前快照。
- 未经过 1.16 的旧用户不能依赖 1.17 直接迁移。
